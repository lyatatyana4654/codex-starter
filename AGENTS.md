# Codex Starter: вход в репозиторий

Начни с текущей просьбы пользователя. Прочитай `START_HERE.md` и общий процесс `docs/workflow.md`. Пользовательские инструкции и границы текущей задачи имеют приоритет над шаблоном.

## Если пользователь начинает свой проект

Этот репозиторий содержит установщик и чистые шаблоны. Выясни целевую папку, если она ещё не указана; для существующего проекта используй его прежнюю папку. Проведи предварительный просмотр по `START_HERE.md`, учитывая уже разрешённую установку и выбранные опции. Не заполняй бизнес-контекст пользователя внутри исходников дистрибутива.

После установки рабочими инструкциями становятся `AGENTS.md`, `PROJECT.md` и `.starter/AUTOPILOT.md` в целевой папке. Не запускай план разработки стартера вместо задачи пользователя. Доверие hooks подтверждается штатно; установщик его не выдаёт.

## Если пользователь меняет сам стартер

Найди актуальный план этой задачи в `plans/` и проверь текущее состояние файлов. Сохраняй универсальность, исходную лицензию и авторство. Добавляй тесты для изменённого поведения установщика и hooks, затем запускай подходящие проверки.

В публикуемых файлах не должно быть персональных данных, секретов или локальных путей конкретного пользователя. Абсолютные пути hooks генерируются установщиком только в целевом проекте. Изменяй файлы своей задачи, сохраняй чужие правки и не затрагивай соседние проекты.
