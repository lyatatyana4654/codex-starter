# Локальный агент Codex

Прочитай корневые инструкции и существующие роли в `.codex/agents/`. Обновляй подходящую роль, если пользователь просит изменить её; не создавай дубликат из-за нового названия задачи.

Из просьбы и контекста установи назначение роли, входные материалы, ожидаемый результат и границы записи. Уточняй только недостающее. Роль исследователя или рецензента по умолчанию получает инструкцию работать без изменения проверяемых файлов.

Создай `.codex/agents/<name>.toml` с полями `name`, `description` и `developer_instructions`. Используй короткое имя из латинских строчных букв, цифр и дефисов; имя файла и `name` должны совпадать. Инструкции ссылаются на существующие правила проекта, а не дублируют их целиком.

```toml
name = "example-reviewer"
description = "Проверяет конкретный результат по критериям проекта."
developer_instructions = """
Прочитай AGENTS.md и критерии текущей задачи.
Исследуй результат без изменения файлов. Сообщи подтверждённые ошибки,
место и способ воспроизведения. Непроверенное обозначай явно.
"""
```

По умолчанию не задавай `model` и уровень рассуждения: они наследуются. Меняй их только при соответствующем поручении или обоснованной задаче в пределах доступных моделей. Разрешения сеанса не расширяются текстом роли; не добавляй bypass и не обещай изоляцию через неподдерживаемые поля TOML.

Проверь синтаксис TOML доступным парсером и загрузку роли в новом сеансе Codex, если это доступно. Статическая проверка не доказывает, что роль уже появилась в текущем чате. Сообщи путь и пример задачи для запуска. Для простого агента не создавай hook или внешнюю интеграцию без потребности в них.
