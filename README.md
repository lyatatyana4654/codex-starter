# Codex Starter

Универсальный стартовый набор для работы с Codex в выбранной локальной папке: правила, планы, память проекта, агенты, навыки и хуки безопасности. Подходит для новой идеи и существующего кода.

Основан на [Claude Code Starter Артемия Миллера](https://github.com/artemiimillier/claude-code-starter), лицензия MIT. Адаптация рассчитана на нативные форматы Codex. Это независимый проект, не продукт OpenAI.

[Скачать ZIP](https://github.com/lyatatyana4654/codex-starter/archive/refs/heads/main.zip) · [Пошаговая инструкция](START_HERE.md) · [Результаты проверок](https://github.com/lyatatyana4654/codex-starter/actions)

## Быстрый запуск

Нужны Python 3.9+ и установленный Codex с поддержкой проектных hooks и TOML-агентов. Основной сценарий — macOS или Linux. [Совместимость](docs/compatibility.md).

1. Нажмите **Code → Download ZIP** в этом репозитории и распакуйте архив. Или скачайте через Git:

   ```sh
   git clone https://github.com/lyatatyana4654/codex-starter.git
   cd codex-starter
   ```

2. В терминале откройте папку скачанного стартера. Выберите папку своего проекта. Для нового проекта сначала создайте её:

   ```sh
   mkdir -p ../my-project
   python3 scripts/install_codex.py ../my-project --business --sounds
   ```

   Последняя команда показывает план полного набора и ничего не записывает. Для минимальной установки уберите `--business --sounds` из этой и следующей команды.

3. Примените план:

   ```sh
   python3 scripts/install_codex.py ../my-project --business --sounds --apply
   ```

4. Откройте **папку своего проекта** в Codex. Проверьте настройки разрешений. В CLI запустите `codex` из этой папки, затем `/hooks`: просмотрите и подтвердите доверие новым обработчикам. Установщик сам доверие не выдаёт.

5. В новом чате напишите:

   > Прочитай AGENTS.md, PROJECT.md и .starter/AUTOPILOT.md. Помоги начать работу с этим проектом. Сначала используй то, что уже есть; спроси только о недостающих вводных.

Подробная инструкция: [START_HERE.md](START_HERE.md).

## Что устанавливается

| Часть | Назначение |
|---|---|
| `AGENTS.md` → `.starter/workflow.md` | Общие правила работы и продолжения задач |
| `PROJECT.md` | Цель проекта, стек, команды проверок, критерии результата |
| `.codex/config.toml` | `workspace-write`, разрешения `on-request`, сеть shell-команд выключена по умолчанию |
| `.codex/hooks/` и `hooks.json` | Проверка видимых опасных команд и подсказка при начале сеанса |
| `.codex/rules/` | Дополнительные запреты для запуска команд |
| `.codex/agents/` | Исследователь, исполнитель, рецензент |
| `.agents/skills/` | Начало проекта и создание специализированного агента |
| `plans/`, `retrospectives/` | План, контрольные точки и выводы после работы |
| `prompts/` | Готовые запросы для продолжения, проверки и расширения проекта |
| `.business/` | Локальный контекст, если подходящего контекста ещё нет |

Модель не закреплена: агенты используют доступную модель родительского сеанса. API-ключи и внешние интеграции в набор не входят.

## Опции первой установки

| Опция | Результат |
|---|---|
| `--business` | Чистый шаблон семи разделов бизнес-контекста |
| `--sounds` | Звук завершения и запроса разрешения |
| `--agent both` | Общие правила для Codex и Claude в одной папке |

Опции можно объединять; выберите их до первой записи. `--business` работает только при отсутствии существующего контекста. Даже минимальная `.business/`, созданная прежней установкой, считается существующим контекстом: повторный запуск не расширяет её шаблоном. Это сохраняет данные пользователя без их чтения установщиком.

Звук зависит от ОС и доступного проигрывателя; он не подтверждает разрешение за пользователя. Добавление `--sounds` после установки меняет определение hooks и может вызвать отказ из-за конфликта. Проверьте и согласуйте изменения файлов вручную.

## Существующий проект

Установщик сохраняет имеющиеся инструкции и добавляет ссылку на общий процесс. Конфликтующие настройки и файлы он не перезаписывает. Сначала запустите без `--apply` и посмотрите сообщение о конфликте.

Установка работает только с выбранной папкой. Глобальные настройки Codex и Claude, Git-индекс и удалённые репозитории не меняются. Повторная установка той же версии с теми же опциями не должна менять файлы. Обновление изменённых файлов требует отдельного сравнения.

Прочитайте [границы защиты](SECURITY.md), [проверку установки](docs/verification.md) и [авторство](NOTICE.md).
