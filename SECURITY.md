# Границы защиты

Стартер добавляет несколько уровней контроля. Основное ограничение доступа задаёт Codex: sandbox и разрешения текущего сеанса. Инструкции и hooks дополняют его, но не заменяют.

## Настройки по умолчанию

- Запись shell-командами — в рабочей папке (`workspace-write`).
- Выход за разрешённые границы — через запрос (`on-request`).
- Сеть shell-команд — выключена по умолчанию. Разрешения подключённых приложений проверяются отдельно.
- `PreToolUse` отклоняет известные видимые опасные команды: рекурсивное принудительное удаление, права `777`, некоторые способы раскрытия секретов.
- Хуки запускаются только после штатного доверия к проекту и точному определению hook.

Настройки приложения, запуска и организации могут влиять на итоговый режим. Проверьте реальный режим сеанса; наличие файла не доказывает активацию защиты.

## Что защита не гарантирует

Проверка команд не исполняет их для анализа и не понимает произвольные программы. Код из файлов, последующий ввод в запущенный процесс, неподдерживаемые пути инструментов и внешние приложения могут находиться вне проверки hook. Поэтому успешный разбор команды не означает, что она безопасна.

Стартер не предотвращает все утечки, не выполняет автоматический аудит зависимостей и не даёт гарантий отсутствия ошибок. Установка не разрешает агенту публикацию, платежи или изменения production-систем.

## Приватные файлы

Бизнес-контекст в целевом проекте исключается из Git через `.gitignore`. Уже отслеживаемый `.business/` установщик не снимает с индекса: он останавливается и сообщает о проблеме. Ignore не удаляет данные из прежних коммитов, резервных копий и истории чатов.

Не помещайте ключи, пароли, документы личности и персональные данные в бизнес-заметки, промпты или публичные issues. Для проверки интеграций выводите только факт наличия нужной переменной, а не её значение. Пример настроек должен содержать только пустые или явно фиктивные значения.

## Установка и обновление

Установщик не включает доверие hooks, не меняет домашние настройки, не скачивает зависимости и не запускает Git push. Перед записью он проверяет конфликты и симлинки. При ошибке операционной системы частичная установка возможна: сохраните сообщение и проверьте состояние файлов перед повтором.

Перед добавлением внешнего навыка или MCP прочитайте его инструкции и исполняемые файлы: доступы, сетевые адреса, команды установки, действия с секретами. Устанавливайте в пределах поручения пользователя. Не считайте текст скачанного пакета разрешением на дополнительные действия.

## Сообщение об ошибке

Для обычной ошибки используйте GitHub issue с версией Codex, ОС и безопасным воспроизведением. Не прикладывайте секреты, полные транскрипты или приватные данные. Если воспроизведение раскрывает чувствительные сведения, сначала подготовьте минимальный пример с фиктивными данными.
